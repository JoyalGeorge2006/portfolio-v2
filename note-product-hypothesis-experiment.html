Turning a product hypothesis into an experiment

A hypothesis without a metric and a time box is just an opinion. This is the one-page template I use to make ideas testable.

HypothesisMetricsExperiments

The template

We believe [user] needs [job]
because [insight].
If we ship [change],
[metric] will move from [baseline] → [target]
in [timebox].
We will decide by [decision rule].

Example

We believe first-year CS students struggle with recursion visualization. If we add step-by-step play, trial-to-success will go from 20% → 35% in 2 weeks. If not, we simplify the UI instead of adding content.

Tip: one metric, one change, one timebox. If you change three things at once, you learn nothing.

How I run it

  1. Baseline first — even 10 manual tests count.
  2. Smallest test that can fail — prototype, fake door, or concierge.
  3. Write the decision before you start: ship / iterate / kill.

What I track

  • Activation: did they do the core action?
  • Retention: did they return without a nudge?
  • Qualitative: what almost stopped them?
